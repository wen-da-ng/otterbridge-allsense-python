# CLAUDE.md

`allsense`, the Python client for AllSense by OtterBridge: connect to a phone running the app, read its streams, cameras and microphones, run commands, read recordings and export MCAP. Package in `src/allsense/`, CLI `allsense`, examples in `examples/` (the docs site includes them, so they must keep running). Public, MIT; PyPI name `allsense`.

## Working here

- **The user makes every commit and push.** Edit files and run the tests, then hand over: what changed, the test results, and a one-line commit message suggestion. Never run `git commit`, `git push`, tags or releases; add no Co-Authored-By line unless asked.
- **Public repository:** never write the user's serials, IPs, Wi-Fi details, home location, tokens or file paths into it. Machine facts go in `CLAUDE.local.md` (git-ignored).

## Test

```bash
.venv/Scripts/python -m pytest -q      # everything against the fake phone; test_examples.py runs the examples
```

Setup: `python -m venv .venv`, then `.venv/Scripts/pip install -e ../otterbridge-allsense-protocol` (the test kit, until it's on PyPI) and `.venv/Scripts/pip install -e ".[dev]"`. Supported `websockets` 12–17.

## How it fits

- Speaks the protocol in `otterbridge-allsense-protocol` (spec at https://docs.allsense.otterbridge.org/PROTOCOL/). Tests use its `allsense_testkit.FakePhone`; a protocol change lands there first, then here.
- The ROS 2 bridge (`otterbridge-allsense-ros2`) depends on this package; `mcap_export.py` mirrors its message conversions.
- `src/allsense/_ros2_msgdefs.py` is generated by `tools/gen_ros2_msgdefs.py` on a machine with ROS 2 Humble.
- Websockets 17.1: open with `connect(...).__enter__()`. Vanishing Wi-Fi doesn't close sockets, hence the 6 s stall watchdog.
